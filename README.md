
# Схема управления ограничениями доступа
Правила доступа основаны на ролях пользователей (принцип RBAC).

### Иерархия проверки прав доступа:
1. Если авторизация не требуется -> ДОСТУП РАЗРЕШЁН.
1. Если user.is_active == False → ОТКАЗ.
1. Если user.role == 'admin' -> ДОСТУП РАЗРЕШЁН. (для админа не требуется создавать разрешение в таблице access_roles_rule)
1. Если редактируется доступ к элементам из списка: Role, BusinessElement, AccessRoleRule -> ОТКАЗ.
1. Если для запрашиваемой операции есть глобальный доступ (_all_permission)-> ДОСТУП РАЗРЕШЁН.
1. Если для запрашиваемой операции есть личный доступ (_permission):
- Если операция 'create' -> ДОСТУП РАЗРЕШЁН.
- Если операция из списка ['read', 'update', 'delete'] и owner_id запрашиваемого ресурса совпадает с user.id юзера который делает эту операцию -> ДОСТУП РАЗРЕШЁН.
В остальных случаях → ОТКАЗ.
